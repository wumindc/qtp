# AI 质量平台业务闭环验收矩阵

> @author codex

## 角色协作方式

- 产品验收官：把用户反馈转成验收矩阵，判定“菜单结构正确”是否真正形成业务闭环。
- 后端领域实现：只负责服务端领域对象、`.do` 接口、服务测试，不改前端。
- 前端交互实现：只负责页面流程、表单、调试台、状态联动，不改后端。
- 集成负责人：合并角色产出，按矩阵逐条验证，未通过项回流给对应角色修正。

## 第一阶段必做验收项

| 编号 | 业务域 | 验收标准 |
| --- | --- | --- |
| A1 | AI 应用接入 | 新增/编辑应用不只填写 URL，必须配置请求方法、鉴权、Header 模板、Body 模板、入参 Schema、出参 Schema、答案路径、成功表达式、流式开关。 |
| A2 | AI 应用接入 | 应用详情内必须有“接入配置”工作台，可以修改协议字段并执行一次模拟调试，显示原始请求、原始响应、解析答案。 |
| A3 | 模型中心 | 页面以模型为主：添加模型时选择供应商，供应商配置作为全局辅助能力，不能反客为主。 |
| A4 | 用例体系 | 用例在具体应用详情内维护，支持从系统预置用例集引用，也支持自建应用用例。 |
| A5 | 测试计划 | 计划在具体应用详情内创建，创建时选择用例范围或手动选择用例，保存后可触发执行。 |
| A6 | 执行历史 | 执行历史在具体应用详情内展示，触发执行后能看到新增批次和基础统计。 |
| A7 | 执行统计 | 应用概览和执行历史能基于真实批次展示通过率、通过/未达标数量、耗时和最近执行记录。 |
| A8 | 信息架构 | 全局一级菜单只保留平台级入口；用例、计划和执行历史作为应用详情内资源，不作为全局平铺资源入口。 |
| A9 | 验证 | 每轮交付必须有类型检查、测试、构建、健康检查和浏览器核心链路验证。 |

## 可执行验收脚本

每轮交付前按以下顺序核验：

1. 在浏览器打开 `/ai-quality-platform/apps`，进入一个应用详情。
2. 在“接入配置”中修改协议字段，执行调试，确认页面出现 raw request、raw response、解析答案和耗时。
3. 在“用例集/测试用例”中引用系统预置用例集，确认当前应用用例数增加。
4. 在“用例集/测试用例”中新建一个应用用例，确认该用例出现在当前应用下。
5. 在“测试计划”中选择用例创建计划，确认计划出现在当前应用下。
6. 点击计划执行，确认“执行历史”出现新批次。
7. 打开“概览”和“执行历史”，确认新批次进入统计和最近执行记录。
8. 打开“模型中心”，确认首屏主体是模型列表，供应商作为全局配置位于次级区域。
9. 执行 `pnpm typecheck`、`pnpm test`、`pnpm --filter web build`、`pnpm check:health`。
