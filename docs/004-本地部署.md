# 本地部署说明

## 启动方式

```bash
eval "$(fnm env)" && fnm use 24
DATABASE_URL="mysql://root:root@127.0.0.1:3306/ai_quality_platform" pnpm db:generate
DATABASE_URL="mysql://root:root@127.0.0.1:3306/ai_quality_platform" pnpm db:push
DATABASE_URL="mysql://root:root@127.0.0.1:3306/ai_quality_platform" pnpm db:seed
docker compose up --build
```

本地非 Docker 调试时可分别运行：

```bash
pnpm dev:services
pnpm dev:gateway
WATCHPACK_POLLING=true pnpm dev:web
pnpm check:health
pnpm check:topology
```

`dev:services` 只启动 `quality-platform-service` 和 `quality-execution-service`。`quality-gateway` 通过公开 API 段把 business/case/plan/ai/review/statistics/system 转发到 platform，把 execution 转发到 execution。

如果本机文件监听较多导致 Next 开发服务出现 `EMFILE`，使用 `WATCHPACK_POLLING=true pnpm dev:web` 作为本地兜底启动方式。

## 访问地址

- 前端：[http://127.0.0.1:3000/ai-quality-platform](http://127.0.0.1:3000/ai-quality-platform)
- Gateway：[http://127.0.0.1:8080/ai-quality-platform/health.do](http://127.0.0.1:8080/ai-quality-platform/health.do)
- MySQL：127.0.0.1:3306 root/root
- Redis：127.0.0.1:6379，密码 sunsharing

## 说明

后端运行单元为 `quality-gateway`、`quality-platform-service`、`quality-execution-service`，前端统一通过 `quality-gateway` 访问后端能力。

Docker Compose 中 gateway 使用 `PLATFORM_SERVICE_HOST=quality-platform-service` 和 `EXECUTION_SERVICE_HOST=quality-execution-service` 访问容器内服务；本地非 Docker 默认仍使用 `127.0.0.1`。

Prisma 使用 7.x 配置方式，连接串放在 `packages/shared-database/prisma.config.ts`，`schema.prisma` 只保留 provider 和模型定义。
