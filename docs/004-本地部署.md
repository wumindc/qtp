# 本地部署说明

## 开发方式：Node 进程

开发环境标准是 Node 本机进程，便于热更新、断点调试和日志定位；Docker 只用于本机 MySQL 依赖。

```bash
eval "$(fnm env)" && fnm use 24
docker compose -f docker-compose.dev-deps.yml up -d
DATABASE_URL="mysql://qtp_app:qtp_dev_password@127.0.0.1:3306/ai_quality_platform" pnpm db:generate
DATABASE_URL="mysql://qtp_app:qtp_dev_password@127.0.0.1:3306/ai_quality_platform" pnpm db:push
QTP_ADMIN_INITIAL_PASSWORD="替换为本地管理员初始密码" DATABASE_URL="mysql://qtp_app:qtp_dev_password@127.0.0.1:3306/ai_quality_platform" pnpm db:seed
pnpm dev:services
pnpm dev:gateway
WATCHPACK_POLLING=true pnpm dev:web
pnpm check:health
pnpm check:topology
```

`dev:services` 启动 `quality-platform-service`、`quality-execution-service` 和 `quality-ai-invocation-service`。`quality-gateway` 通过公开 API 段把 business/case/plan/ai/review/statistics/system 转发到 platform，把 execution 转发到 execution；AI 模型调用由 platform/execution 通过内部 AI invocation service 完成。

如果本机文件监听较多导致 Next 开发服务出现 `EMFILE`，使用 `WATCHPACK_POLLING=true pnpm dev:web` 作为本地兜底启动方式。

## 生产方式：Docker Compose

生产环境标准是 Docker Compose 全栈部署，只暴露 nginx 最终入口，内部服务不映射宿主机端口。首次部署需要先设置 `QTP_AUTH_TOKEN_SECRET`，再用 `QTP_ADMIN_INITIAL_PASSWORD` 显式初始化管理员密码。

```bash
export MYSQL_ROOT_PASSWORD="替换为生产 root 管理密码"
export MYSQL_USER="qtp_app"
export MYSQL_PASSWORD="替换为生产应用库密码"
export MYSQL_DATABASE="ai_quality_platform"
export QTP_AUTH_TOKEN_SECRET="替换为长随机密钥"
docker compose up --build -d mysql
QTP_ADMIN_INITIAL_PASSWORD="替换为管理员初始密码" docker compose run --rm quality-platform-service pnpm db:seed
PUBLIC_WEB_PORT=5670 docker compose up --build -d
```

生产访问：

- 系统入口：[http://127.0.0.1:5670/ai-quality-platform](http://127.0.0.1:5670/ai-quality-platform)
- 聚合健康：[http://127.0.0.1:5670/ai-quality-platform/health.do](http://127.0.0.1:5670/ai-quality-platform/health.do)

## 开发访问地址

- 前端：[http://127.0.0.1:3000/ai-quality-platform](http://127.0.0.1:3000/ai-quality-platform)
- Gateway 聚合健康：[http://127.0.0.1:8080/ai-quality-platform/health.do](http://127.0.0.1:8080/ai-quality-platform/health.do)
- MySQL：127.0.0.1:3306 qtp_app/qtp_dev_password

## 说明

后端运行单元为 `quality-gateway`、`quality-platform-service`、`quality-execution-service` 和 `quality-ai-invocation-service`，前端统一通过 `quality-gateway` 访问后端能力。开发时浏览器从 `web:3000` 调 `gateway:8080`；生产时浏览器只访问 nginx 暴露的最终入口。

Docker Compose 中 nginx 访问 `web:3000` 和 `quality-gateway:8080`，gateway 使用 `PLATFORM_SERVICE_HOST=quality-platform-service`、`EXECUTION_SERVICE_HOST=quality-execution-service` 和 `AI_INVOCATION_SERVICE_HOST=quality-ai-invocation-service` 访问容器内服务；这些内部服务不映射宿主机端口。本地 Node 开发默认仍使用 `127.0.0.1`。

Prisma 使用 7.x 配置方式，连接串放在 `packages/shared-database/prisma.config.ts`，`schema.prisma` 只保留 provider 和模型定义。
