# 执行历史详情页设计 (Execution History Detail Design)

## 设计概述

基于当前生成的 UI 效果图，为了提升执行历史详情页的可用性和专业度，我们设计了一个包含统计分析和详细用例列表的暗色系 (Dark Mode) 面板。该页面旨在让开发者或测试人员快速掌握单次执行的全局状况，并能迅速定位失败用例。

## 页面结构规划

该页面将主要分为三个逻辑区域：

### 1. 顶部状态栏 (Header Section)
*   **标题与基础信息**：显示执行的计划名称、执行的 ID（如 EXEC-8412-RTS）。
*   **状态标签 (Status Badge)**：直观显示当前的最终结果（如 `FAILED`、`PASSED`、`RUNNING`）。
*   **元数据**：显示开始时间、持续时长 (Duration) 以及触发方式 (Triggered by)。
*   **操作按钮**：如“重新运行失败用例 (Rerun Failed)”、“导出报告 (Export Report)”。

### 2. 统计概览卡片 (Summary Cards)
使用四个带有毛玻璃效果 (Glassmorphism) 的数据卡片展示核心指标：
*   **总用例数 (Total Test Cases)**
*   **通过率 (Pass Rate)**：附带微型柱状图或趋势线。
*   **通过数量 (Passed)**：使用绿色标识，可搭配 Check 图标。
*   **失败数量 (Failed)**：使用红色标识，搭配 X 图标，引起视觉注意。

### 3. 数据分析与详情 (Analytics & Detail List)
分为左右（或上下，根据屏幕自适应）两部分布局：
*   **图表区 (Donut Chart)**：使用环形图直观展示 Passed/Failed/Skipped 的比例，中心数字为总数。
*   **用例列表 (Test Case Data Table)**：
    *   **列配置**：用例名称 (Test Case Name)、模块 (Module)、状态 (Status)、耗时 (Duration)、操作 (Actions)。
    *   **注意**：遵循项目规范，列宽自适应不固定设置。
    *   **操作**：每行提供 "View Log" 按钮，点击可弹出抽屉或模态框查看具体的报错日志或执行输出。

## 技术选型与实现思路

1.  **UI 框架**：使用 React + TailwindCSS 构建。风格将严格对齐当前系统的极简暗黑风 (Minimalist Dark Mode)，主背景色使用纯黑 (`#000000` 或相近)，卡片使用深灰无渐变的扁平化设计，去除复杂的毛玻璃和阴影效果。
2.  **排版与颜色**：主要使用纯白色作为主标题文字，浅灰作为副标题和描述文字。状态颜色保持克制，仅在必要时使用低饱和度的绿色 (Pass) 和红色 (Fail)。
    *   `ExecutionDetail.tsx` (主容器)
    *   `HeaderBoard.tsx` (顶部栏)
    *   `SummaryCards.tsx` (统计卡片组)
    *   `ResultChart.tsx` (环形图表)
    *   `TestCaseList.tsx` (用例列表视图)
    *   `mock-hooks.ts` (独立的数据 Mock Hook，用于初期静态页面开发)
